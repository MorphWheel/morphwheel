## Interpretations and additions (RD-7 to RD-10 and T7, approved with the sprint)

1. **Compress for PNG** (RD-7, the open point of phase-3 §2.2). JPG, WebP and AVIF are resized to a
   2048 px longest side and re-encoded at quality 80. PNG has no quality: it is resized, re-encoded
   with `optimize`, and turned into a palette image **only when that is lossless** (at most 256
   colors, no alpha, and the pixels compared after the conversion). Nothing is ever upscaled. The
   worker, not the converter, judges "smaller" against the source's size.
2. **The integrity-level gate** (RD-8, the S2 security note). Window classes are spoofable and OLE
   accepts drags from lower-integrity processes. A press in a process whose mandatory integrity
   level is below ours is not a drag source (logged at WARNING). A level that can't be read is
   allowed, so a protected process never breaks an ordinary drag.
3. **Contract changes** (RD-9, phase-4 §4.1). `Task.source_format` carries the sniffed format
   (RF-3); `DropRequest.files` carries `FileInfo`s, not bare paths; `FileInfo.sniffed` says whether
   the bytes were read. The worker sniffs the header itself when the hint is `None`.
4. **Placeholders are delete-on-close, commits are renames** (RD-10, a stronger form of §4.4's
   `os.replace` sketch). A killed worker can't leave an empty `photo.jpg` behind, and nothing in the
   engine ever lands on an existing path. This came out of the plan review (below).
5. **A target for criterion 4.** A 12 MP HEIC decoded and written as JPG at quality 90 takes
   0.7 s on this machine (synthetic image, pillow-heif 1.8.1). Proposed target: **≤ 1.5 s** for a
   12 MP HEIC → JPG on the dev machine, measured in the worker (`duration_ms` is in the log).
6. **The quality defaults** (phase-3 §6.2) hold up on a synthetic 12 MP photo-like image:

   | Format | Quality | Size | Encode time | PSNR |
   |---|---|---|---|---|
   | JPEG | 80 / **90** / 95 | 600 / **880** / 1284 KB | 0.02–0.06 s | 50.7 / **53.5** / 56.1 dB |
   | WebP | 75 / **85** / 92 | 114 / **198** / 379 KB | ~1.0 s | 45.6 / **46.9** / 49.0 dB |
   | AVIF | 60 / **70** / 80 | 180 / **228** / 306 KB | 0.23 s | 49.2 / **50.4** / 51.7 dB |
   | Compress (JPEG, 2048 px) | 70 / **80** / 90 | 159 / **213** / 336 KB | | |

   The defaults sit at the knee of each curve. WebP is the slow one (about 1 s at 12 MP; Pillow's
   default method), which is still inside the "working toast" budget. Synthetic numbers: the user's
   real photos will differ, and the settings page (S5) lets them be changed.
7. **Manifests speak `FormatId`s.** `output = "tiff"` instead of the draft's `output_ext`, the same
   vocabulary `accepts` already uses.
8. **The toast strings handle the English plural in the source** (`%n file(s)`); translations get
   the count and pick their own form (D3).

## Plan review (two lenses) and what it changed

Before any code, the plan was attacked from a data-loss lens and a process-model lens.

- **Data loss.** The original sketch (a 0-byte placeholder, `os.replace` at commit) had two holes: a
  worker killed on a timeout leaves an empty file under the *final* name, and "the placeholder is
  still 0 bytes" doesn't prove it is ours. Fix: delete-on-close placeholders and `rename` (RD-10),
  the temp path reported to the pool and swept after a kill, the file id in the fingerprint, stage-
  aware error mapping (an unreadable source is `UNREADABLE`, not `WRITE_FAILED`), and `recycle`
  refusing drives without a Recycle Bin (where the shell would delete for good).
- **Process model.** `set_executable` works for a frozen parent and a different frozen child (the
  child needs `freeze_support()` first and the target importable from its own bundle; `WINEXE`
  skips re-running the parent's main). The S0 probe can't verify it (its worker lives in the probe's
  `__main__`), so the app got `--worker-check`. Pool threads wait on the pipe *and* the process
  sentinel; shutdown drops queued tasks and runs before the `QApplication` dies; pool → dispatcher
  goes through an explicit queued connection. The HEIC wheel's DLLs live at the wheel root (plus a
  `platlib` folder), so the extractor takes `pillow_heif/`, `*.pyd` and `*.dll` flat.

## Security review

A review of the new surface (output-path derivation, the zip extraction, pickle over the worker
pipe, plugin loading, `SHFileOperationW`, the Undo path, the integrity gate, the fingerprint, the
sniffer, the spec) found **no exploitable issue above its bar**. Three notes were acted on:

- The toast labels now render **plain text**: a drop-supplied file name that looks like markup can't
  become rich text (an image tag pointing at a network share in a name would otherwise make the
  label fetch it). Explorer can't produce such names, but a drag from another process could.
- Undo compares the **NTFS file id** too (`CreatedFile.file_id`, set at commit), as its docstring
  promised: a file deleted and re-created with the same size and time is "changed".
- The downloaded engine's folder is **appended** to the worker's `sys.path`, like plugin folders, so
  it can't shadow the app or the standard library.

Judged safe as built: names come from `source.name` (no separators), exclusive creates refuse
existing files and links, the rename never replaces; the wheel is hashed before any byte is written
and extracted from the same bytes; the pipe is a single-instance named pipe held by the worker
alone; `recycle` acts only on an absolute, existing file on a fixed drive; the integrity gate fails
open only when a token can't be read, which a low-integrity process can't force.

## Findings

1. **Explorer's default is `Move`, and the engine never relies on it being blocked twice.** Nothing
   new, but S3 is the first sprint where a wrong drop would have cost a file: every test that writes
   checks the source folder's listing before and after.
2. **A scanner holds a dying handle.** The killed-worker test saw the delete-on-close placeholder
   linger for a moment after `TerminateProcess`; the file disappears when the scanner's handle
   closes. The test waits up to 5 s. In production the same happens, silently.
3. **`os.replace` on Windows fails while any handle is open on the destination** (`ERROR_ACCESS_DENIED`),
   and `os.rename` fails when the destination exists. Both facts drove RD-10.
4. **The build has two PYZ archives**, one per executable (stdlib and Pillow twice, a few MB). S7
   can MERGE them if size matters.
5. **Windows `Downloads` can live on OneDrive** (it does on the dev box, under a Hebrew path), and
   the fallback folder follows it. Noted for the toast text ("Saved to Downloads\Morphwheel").
6. **The code review** (8 findings, fixed): the sniffer stat'ed files on the GUI thread; the
   application recorded a job's screen *after* `submit`, which leaked for all-skipped jobs; queued
   tasks still ran after `shutdown`; tasks hung forever when no worker could start (now they fail
   after three spawn failures); a pool that refuses a task left the job open; an unused constant
   that promised an unimplemented rule; a convoluted size helper; a duplicated test fixture.

## The cleanup passes

Four lenses (reuse, simplification, efficiency, altitude) reviewed the finished code. Applied:
`TaskResult.failure` as the one builder of a failed result (worker, pool, dispatcher); one
`try`/`except` and an exception-to-code table in the worker instead of seven abort-and-return
blocks; `WorkerPool.run` never raises (a stopped pool fails the task itself, so the dispatcher has
no special case); one job table in the application instead of four parallel fields; a persistent
sniffer thread that skips superseded requests, with the stat moved off the GUI thread; a cached own
integrity level and one token-handle helper in `system.py`; Downloads from `platformdirs` instead of
50 lines of ctypes; a lossy-format table shared by convert and compress; `ImageChops.difference`
instead of two `tobytes()` copies in the palette check; the engine folder appended to `sys.path`
through the loader's one helper; `is_writable` and other unused helpers removed; the window keeps one
list of files; a mislabeled HEIC now opens on the second try once the engine registers.

Skipped: adding `input_format` to the plugin API (an API change belongs to S6's review of the
SDK; the converter re-reads 32 bytes instead), a `sniff_path` helper in `core.formats` (core stays
free of I/O by design), carrying the source size on `TaskResult` to save one stat per toast (a
contract change for a negligible gain), and deleting `output_policy.output_directory` (approved S1
code; the worker's fallback is the live mechanism, noted for S5's settings work).
