## Interpretations and additions (RD-15 to RD-24, for approval with the sprint)

1. **RD-15, RD-21.** The settings file is read tolerantly and never overwritten by a save that didn't
   read it first; a file that couldn't be read is read again before every write until it reads.
2. **RD-16.** A wheel-size change asked for while the wheel is visible waits for the hide.
3. **RD-17.** The toasts' final form: window-opacity fades (not a drop target), the buttons as data
   turned into signals, the hold while the wheel is up, the single-file working toast after 1 s, the
   dismissed working key that stays dismissed.
4. **RD-18.** Which problems light the tray's red dot: critical results only.
5. **RD-19.** The settings window in the Windows-settings style: no OK or Cancel, every control writes
   at once, sliders once per gesture; Mica stays open.
6. **RD-20.** The first-run bubble is a sticky toast in the work-area corner, acknowledged by Got it,
   Settings, ✕, opening the settings or the first drop.
7. **RD-22.** Modal only before the controller starts; the Details window; the HEIC consent names the
   wheel, the size, PyPI and the GPLv2 with Cancel as the default; the catalog refreshes in place.
8. **RD-23.** The Run value is the truth at start and the setting after a change; only the installed
   app touches it; one instance per session through a fixed mutex and a per-session, user-only pipe.
9. **RD-24.** One `translate` call shape, guarded by a test against `lupdate`; English ships without a
   catalog; a `language` setting with no picker; Windows' language list walked by hand to the first
   English entry; the direction follows the language in effect; the wheel pinned left-to-right; the
   alternative not taken (an English plural-only catalog) recorded for a decision.

## Plan reviews and what they changed

Every file's plan was attacked before code (one or two lenses each), and every review found something
that would have shipped broken:

- **File 1:** a settings file that can't be read at startup must never be overwritten by the next
  save (the re-read-and-merge store).
- **File 2:** no application-modal Details box (it would block every toast button and make the wheel
  refuse drags); nothing shows while the wheel is visible; the animations as widget-owned attributes.
- **File 3:** the tray built before the settings are pushed; one `_refresh` owning the timer; every
  slot a bound method (a lambda slot on a child had crashed the suite in file 2).
- **File 4:** a debounce per slider (thirty writes a second otherwise); no refresh over an edit in
  progress; a plain window, not a `QDialog`.
- **File 5:** re-wording the bubble on every settings change would have brought it back right after
  the first drop with animations on; opening the settings acknowledges it instead. The same review
  surfaced the store's stand-in-defaults hazard (RD-21).
- **File 6:** the app holds the download job until its result is handled (a job held only by its
  thread is freed with it, and a freed sender's queued signal never arrives).
- **File 7:** the installer's checkbox would have been deleted on the first run; the mutex released
  before a restart from elevated; tests never reaching the real Run key or pipe.
- **File 8:** `QTranslator.load(QLocale.system(), …)` walks every language Windows lists, so this
  machine would have picked a Hebrew catalog the day one ships; the AST guard had to collect the NOOP
  marks and the class context of `self.tr`.

## Findings

Across the sprint the code reviews found 36 items (31 fixed, 5 skipped with a reason or a decision
recorded), the security reviews 2 real items (the store's no-op shortcut after a re-read; the pipe
open to every local account), both fixed, and the four cleanup lenses applied 100 of 122 findings.
One crash was bisected from the full suite (file 2): a `QTimer` child whose lambda slot captured its
parent held the parent's last reference; the rule (bound-method slots only on child objects) is in
`manager.py` and `tray.py`. One real UI finding came from the Hebrew render in file 8: a `QLabel`
aligns "leading" by each line's own script, so a Latin file name sat at the wrong edge under a Hebrew
title; the toast now aligns to the layout's edge.

## UI pass

Every surface was rendered offscreen and inspected: the toasts in every kind, Dark, Light and High
Contrast, LTR and RTL; the tray in every state and all eight working frames at three sizes on a dark
and a light taskbar; the three settings pages with the problems bar, LTR and RTL; the bubble in three
schemes; the Details window, the consent and the elevated box, LTR and RTL; and in file 8 a toast
with a compiled Hebrew catalog on the Windows platform (offscreen has no fonts), mirrored, with Qt's
own Cancel in Hebrew. Zero durations with animations off are proven by tests in every file.
