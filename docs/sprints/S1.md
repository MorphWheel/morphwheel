## Interpretations and additions (no approved rule changed)

1. **"Hide immediately on release without a drop"** is implemented as a short `RELEASING` state. The raw
   mouse-up arrives 1–4 ms *before* OLE's Drop (spike log). The wheel hides as soon as we *know*
   nothing was dropped: on the DragLeave that OLE sends for releases over the hub, a gap or the halo,
   or after a 150 ms grace period.
2. **One unsupported file blocks the whole drag** (for example a PNG plus an animated GIF). The
   reason shown is the specific one ("animated"), not the generic "no common format". Precedence:
   folder > not local > engine missing > animated > unknown > unsupported format.
3. **`ErrorCode.ENGINE_MISSING`** was added to the phase-4 contract for A6.
4. **Core holds no clocks and no strings.** Time comes in as `t_ns`. Reasons and hub content are
   enums or data, so the UI translates them (D3a).
5. **Builtin status comes only from discovery** (`Target.is_builtin`). A third-party target that copies
   a builtin id, provider and slot stays in the More arc, which is tested.

## Bugs found in review and fixed before approval

- **Stale trigger-key state.** The poller stops while idle. A Shift released after a drop was never
  seen, and the *next plain drag* would have opened the wheel without Shift. Fix: every
  `PointerDown` starts with the key "up". Covered by two consecutive-gesture tests.
- **Give-up had no exit.** A wheel that never got a plan stayed "open", so a new Shift couldn't
  reopen it. Fix: a `GiveUp` event dismisses the wheel like leaving the halo does.

## Carry-overs into S2 (also in `progress.md`)

- DragEnter must **always** go through `force_copy`, even before arming. Qt sends no DragMove to a
  window that ignored DragEnter (spike). `SessionView.accepts_drop` governs DragMove and Drop only.
- Compute `more_center_deg` with `geometry.more_arc(center, screen, MORE_ARC_MAX)`, the worst-case
  count, so the arc can't run off-screen when plugins are added.
- Feed `GiveUp` into the gesture machine when the session reports `HubKind.GAVE_UP`.

## Fix to an S0 deliverable

`tools/drag_probe.py` used to hide the overlay on the raw mouse-up. Because the Drop arrives after
the mouse-up, that could lose drops during checklist C1–C12. It now waits for the Drop or a DragLeave,
with a 150 ms fallback. The frozen exe was rebuilt and smoke-run.
