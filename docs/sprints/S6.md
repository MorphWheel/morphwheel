# Sprint S6: The plugin system (M3). Report

**Dates:** 2026-11-12 to 2026-11-18. **Status:** ✅ approved 2026-11-18 (A2).

M3 in one sentence: a third party can add a converter to the wheel. The folder is scanned, the
registry turns the settings into targets and into what the workers may load, the Plugins page and
the trust prompt put the user in charge, the loader keeps every plugin inside its own folder, the
sample plugin shows the way in thirty lines, and the tests prove that a plugin that crashes, hangs,
breaks or tampers never takes the app down.

## Interpretations and additions (RD-25 to RD-28)

RD-27 was reviewed and approved on 2026-11-18; RD-25, RD-26 and RD-28 are proposed with this
sprint. In one line each (the full text is in `docs/decisions.md`):

- **RD-25, discovery:** the folder is named after the id; a folder without a manifest is reported, as is a link (never followed) and a manifest at the root; a third-party manifest claiming a builtin's id is broken, not demoted; nothing in a manifest can stop the scan; a broken plugin carries a kind and a raw reason.
- **RD-26, the registry and the trust gate:** `enabled` is the trust record, keyed by id (a folder replaced under the same id stays enabled; a per-version prompt is post-MVP); one stable row order; unknown ids ignored and logged; the workers are configured with the enabled plugins' specs only and a change respawns each before its next task (the first conversion after a toggle waits for a cold start); the folder is scanned at start and on the page's explicit rescan.
- **RD-27, the page and the prompt (approved):** the registry pushed into the page; checking asks, unchecking writes; the prompt non-modal with Cancel as the default; the order write deferred past Qt's drop handler; broken folders in a second list; the overflow counted by target; Open plugins folder creates the folder; three deltas from the mock (no author line, a check box, a hint sentence).
- **RD-28, one module or package per plugin:** the loader's folder rule with the refusals listed above; the manifest's reserved names; the registry's clash check with enabled-first precedence (amends RD-26); the naming advice; an isolated per-plugin finder noted as a post-MVP option.

## Plan reviews and what they changed

Every file was planned, spiked where Qt or the OS could surprise, and reviewed before code:

- **File 1:** a hostile manifest could escape as `UnicodeDecodeError` or `RecursionError` (both verified in the venv); a junction to a dead network path would hang the GUI in `stat`. Both folded in. Spiked: `DirEntry.is_dir(follow_symlinks=False)` is True for a junction, so `is_junction()` goes first.
- **File 2:** a `Configure` message to a live worker can't unload a module, a `sys.path` entry or a cached converter (disable A, enable B with the same module name, and A's code runs under B's id), so a change respawns; the spawn takes the config and its version as one pair under the lock; the app test's fixture had to be copied under its id or the "disabled by default" assertion would have passed vacuously.
- **File 3:** broken folders inside the drag list would corrupt the order display; the order write ran inside Qt's drop handler while the push rebuilt the list under it (a zero-timer deferral and a push that diffs the ids); spiked: a real internal drop inserts a copy and removes the source and fires `itemChanged` for the half-built copy.
- **File 4:** one rule with one message instead of two overlapping checks; sibling helpers as the same bug class; the registry refusing a clash deterministically rather than per worker. Spiked: a spawned worker inherits the parent's `sys.path`, whose first entry is the app's own directory.
- **File 7:** a 3 s task timeout also governed a cold worker's first task (it imports Pillow and the plugin before reading it), so the tests use 10 s; the worker's pid now proves the respawn.

## Findings

- **Pre-existing on this machine:** four app tests (and every test that stops a pool with a spawn in flight) print a Windows access-violation dump from `popen_spawn_win32` under `_spawn` while the main thread is in `WorkerPool.shutdown`; the tests pass. Reproduced at HEAD with the S6 work stashed; absent from the last green CI log. Recorded as an open item; not explained.
- **A test-order leak the folder rule caught:** in-process worker tests appended fixture plugin folders to the pytest process's `sys.path`, and spawned workers inherit that path, so an installed copy of the tampering plugin resolved to the fixture's original file and was refused. An autouse fixture now restores `sys.path` after every test.
- **Qt's English plural rule can't inflect a verb** (the overflow line was reworded), and after `moveRow` the current index travels with the item, so the move buttons must be refreshed by hand.
- **A converter's error message never reached the toast**, though `plugins/api.py` said it did; the toast shows a fixed sentence per error and the message goes to the log. The docstring and the author's page say so now.
- **The registry's first precedence was wrong:** an installed, disabled plugin could knock out an enabled one below it by claiming its module name; enabled plugins claim first now.

## UI pass

The Plugins page rendered offscreen in both directions: check boxes and the buttons mirror under RTL, the broken list sits apart with a capped height, the prompt's default frame is on Cancel. No stylesheet, no tooltips. Space toggles a row (asks, and reverts until the prompt answers), Alt+Up and Alt+Down move it. The real mouse drag and the prompt by hand are row C40.

## Proof posture

- **Proven by tests:** everything in the traceability table; the gate both ways with real worker processes; the sample plugin end to end; the four failure modes through the real app.
- **Reasoned from the construction:** the frozen build puts bundled modules ahead of plugin folders, so a plugin named like one is refused by the folder rule (row C41 by hand); the catalog and worker refresh run synchronously on the GUI thread, so no drop lands between the two steps; two folders mapping to one id on a case-sensitive volume (the duplicate guard, untestable on Windows).
- **By hand (👤):** C40, C41; the first conversion after a toggle on a real machine (a cold start).
